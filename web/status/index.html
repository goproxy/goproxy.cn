The browser checks two proxy endpoints. The terminal commands below can also verify a full module download. For service incidents and maintenance, see the service status page.

Verify in Bash or Zsh

The first request fetches module version metadata. The second checks whether Goproxy.cn proxies the default checksum database.

curl -fsS -w '\n' https://goproxy.cn/golang.org/x/text/@v/v0.3.2.info curl -fsS -o /dev/null -w '%{http_code}\n' https://goproxy.cn/sumdb/sum.golang.org/supported

This command downloads a public module through Goproxy.cn with an empty module cache and the public checksum database enabled. It removes the temporary cache on exit.

( probe_cache=$(mktemp -d) && trap 'GOMODCACHE="$probe_cache" go clean -modcache' EXIT && cd "$probe_cache" && GOMODCACHE="$probe_cache" GOWORK=off \ GOPROXY=https://goproxy.cn GONOPROXY=none \ GOSUMDB=sum.golang.org GONOSUMDB=none \ go mod download -json golang.org/x/text@v0.3.2 )

Common failure modes

Timeout or TLS error

Try the same endpoint with curl, then check DNS, system certificates, HTTPS_PROXY and CI egress rules.

HTTP 404 or 410

Check the module path and version. If you configured ,direct, Go will try version control directly after either response.

A private module path was sent to a public proxy

Follow the private module setup guide to make sure GOPRIVATE matches the module path prefix. If you set GONOPROXY or GONOSUMDB separately, check those patterns too.
